Set PASSWORD_LOGIN_ENABLED=false once every user has linked single sign-on. The login page then hides the password form and the three password endpoints return 403. The first-admin setup still works, so a fresh instance can always be bootstrapped.

WARNING

Disabling password login is a one-way door until you re-enable it. Existing local accounts that have no OIDC link can no longer sign in while the flag is off. To recover, set PASSWORD_LOGIN_ENABLED=true and restart the backend.

Trusted Reverse-Proxy Authentication (Optional) ​

When a reverse proxy already authenticates users (for example Traefik BasicAuth or an SSO gateway), LibrisLog can reuse that identity and create a browser session automatically. The forwarded value is matched against an existing user's email address; unknown values are ignored and never create accounts.

VariableDescriptionDefault
TRUSTED_PROXY_AUTH_ENABLEDEnable proxy-header authenticationfalse
TRUSTED_PROXY_AUTH_HEADERHTTP header carrying the authenticated identityX-Forwarded-User
TRUSTED_PROXY_AUTH_IPSComma/space-separated IP addresses or CIDR ranges allowed to send the header. Empty disables the feature even when enabled.(none)
TRUSTED_PROXY_AUTH_SECRETOptional shared secret the proxy must also send in X-Trusted-Proxy-Secret. Empty means no secret is required.(none)
TRUSTED_PROXY_AUTH_USER_MAPOptional proxy_user=email pairs, separated by commas or spaces. When set, a forwarded value is translated through the map before the email lookup; values not in the map are used as the email directly.(none)

The feature fails closed: if the IP list or the header name is empty, the middleware logs a warning at startup and stays inactive. * in the IP list trusts every client and is only safe on an isolated network. Invalid IP entries are logged and ignored. CIDR ranges such as 172.18.0.0/16 are supported, and IPv4-mapped IPv6 addresses are normalised.

WARNING

Only enable this when LibrisLog is reachable exclusively through the trusted proxy. Anyone who can connect directly and spoof the header could impersonate a user.

The IP check uses the address LibrisLog sees as the connecting peer. If Uvicorn's proxy-header handling rewrites that address from X-Forwarded-For (controlled by FORWARDED_ALLOW_IPS or --proxy-headers), a client can make the request look like it came from the proxy. In that case, set TRUSTED_PROXY_AUTH_SECRET and have the proxy inject it, or restrict FORWARDED_ALLOW_IPS to the proxy's address only.

Other containers on the same Docker network can also reach the backend and present the header, so use the shared secret in multi-container setups.

Example Traefik labels for a BasicAuth-protected deployment. The BasicAuth user name can be any proxy username as long as it appears in TRUSTED_PROXY_AUTH_USER_MAP:

yaml
labels:
  - "traefik.http.middlewares.librislog-auth.basicauth.users=alice:$$apr1$$..."
  - "traefik.http.middlewares.librislog-auth.basicauth.headerfield=X-Forwarded-User"
  - "traefik.http.middlewares.librislog-auth-secret.headers.customrequestheaders.X-Trusted-Proxy-Secret=change-me"
  - "traefik.http.routers.librislog.middlewares=librislog-auth,librislog-auth-secret"
  - "traefik.http.services.librislog.loadbalancer.server.port=8000"

Traefik only sets the authenticated-user header when basicauth.headerfield is configured; its default is empty. The header value is the BasicAuth user name. If you do not set TRUSTED_PROXY_AUTH_USER_MAP, that name must be the LibrisLog account email. The BasicAuth and Headers rules must use different middleware names, as in the example above.

Configure LibrisLog with the proxy's address, the header Traefik sets, and a mapping from proxy usernames to account emails:

dotenv
TRUSTED_PROXY_AUTH_ENABLED=true
TRUSTED_PROXY_AUTH_HEADER=X-Forwarded-User
TRUSTED_PROXY_AUTH_IPS=172.18.0.0/16
TRUSTED_PROXY_AUTH_SECRET=change-me
TRUSTED_PROXY_AUTH_USER_MAP=alice=alice@example.com,bob=bob@example.com

Mapping keys are matched case-insensitively. A forwarded value that is not present in the map is treated as an email address, so mixed deployments can map some proxy users and pass others through directly. Duplicate keys keep the last value and log a warning; mapping values without an @ are ignored so a typo is visible in the logs.

WARNING

The pass-through fallback is only safe when the proxy alone decides the username and users cannot choose arbitrary values. If a user can set their proxy username to another person's email address, they can be signed in as that person. When proxy usernames are user-controlled, map every allowed username explicitly.

Email matching is case-insensitive for ASCII addresses.

The IP must be the address LibrisLog sees as the connecting peer (the proxy container), not the end user's address. With Docker Compose, use the proxy container's static IP or the Docker network subnet.

With proxy authentication enabled, logging out clears the LibrisLog session, but the next request from the same proxy signs the user in again. This is expected: access is controlled by the proxy, not by LibrisLog.

Local Development

For local development, use Mailpit (included in docker-compose.dev.yml):

bash
MAIL_SERVER=localhost
MAIL_PORT=1025
MAIL_STARTTLS=False
MAIL_SSL_TLS=False
MAIL_USERNAME=
MAIL_PASSWORD=
MAIL_FROM=noreply@localhost

The Mailpit web UI is available at http://localhost:8025 to inspect sent emails.

Book Import Sources ​

Every search source can be switched on or off individually. At least one source must be able to answer: if every source is disabled, or the only enabled ones are Hardcover and Google Books without their credentials, the backend refuses to start and logs an error naming the variables to set.

VariableDescriptionBuilt-in defaultRecommended
OPEN_LIBRARY_IMPORT_SEARCH_ENABLEDQuery Open Librarytruetrue
BNF_IMPORT_SEARCH_ENABLEDQuery BnF (French national library), title and ISBNtruetrue
INVENTAIRE_IMPORT_SEARCH_ENABLEDQuery Inventaire.io, ISBN onlytruetrue
LIBRARY_OF_CONGRESS_IMPORT_SEARCH_ENABLEDQuery the Library of Congress, title and ISBNtruedepends, see below
DNB_IMPORT_SEARCH_ENABLEDQuery the Deutsche Nationalbibliothek (German National Library), title and ISBNtruetrue
HARDCOVER_IMPORT_SEARCH_ENABLEDQuery Hardcover.app (also needs HARDCOVER_APP_API_TOKEN)truefalse unless a token is set
GOOGLE_BOOKS_IMPORT_SEARCH_ENABLEDAllow the Google Books fallback (also needs GOOGLE_BOOKS_API_KEY)truefalse unless a key is set
GOOGLE_BOOKS_API_KEYGoogle Books API key (see API Keys)empty(none)
HARDCOVER_APP_API_TOKENHardcover.app API token (see API Keys)empty(none)

The built-in default is true for every source, so upgrading never silently drops a source that worked before these switches existed. .env.example sets the two keyed sources to false, which is what you want unless you have configured a key or token.

BnF, Inventaire, the Library of Congress, and the German National Library need no API key and are enabled by default.

Hardcover and Google Books cannot answer without credentials. Either way they are handled the same way: if the switch is on and the key or token is empty, the source is reported as skipped in the search progress list and no request is sent, so it never slows a search down. To use either, set its credential and keep the switch on:

bash
GOOGLE_BOOKS_API_KEY=your-key
GOOGLE_BOOKS_IMPORT_SEARCH_ENABLED=true

Inventaire answers ISBN lookups only; it has no title search, so on a title search it is reported as skipped. Google Books runs last, only when every other enabled source returned nothing. Setting GOOGLE_BOOKS_IMPORT_SEARCH_ENABLED=false also turns off the on-demand Search Google Books too button.

Warning: The Library of Congress SRU endpoint (http://lx2.loc.gov:210/LCDB) is only reachable over plain HTTP. Queries are therefore unencrypted and can be observed or altered on the network path. It is the official, documented LC SRU server and returns public bibliographic data only, but set LIBRARY_OF_CONGRESS_IMPORT_SEARCH_ENABLED=false if unencrypted egress to port 210 is not acceptable in your environment. The other sources are all HTTPS.

Telemetry ​

LibrisLog sends minimal, anonymous installation telemetry (see Telemetry) to understand how many installations exist and on which platforms they run. It is an installation census. No user, book, reading, or host data is ever collected.

The telemetry server is open source (github.com/codebude/librislog-telemetry) and the aggregated results are public at metrics.librislog.app.

VariableDescriptionDefault
TELEMETRY_DISABLEDDisable all telemetry (true/false)false
TELEMETRY_ENDPOINTTelemetry API endpointhttps://metrics.librislog.app/api/telemetry
TELEMETRY_TIMEOUT_SECONDSHTTP timeout for telemetry requests10

To opt out entirely:

bash
TELEMETRY_DISABLED=true

Validation Rules ​

  • API_KEY_ENCRYPTION_KEY must be a real secret key (minimum 32 characters). Do not use the placeholder value from .env.example. If left as placeholder or set to a weak value, API key creation will fail.
  • When OIDC_ENABLED=true, all three OIDC variables must be set.
  • GOOGLE_BOOKS_API_KEY and HARDCOVER_APP_API_TOKEN are optional. See API Keys for how to obtain them. The app runs fine without them using Open Library, BnF, Inventaire, the Deutsche Nationalbibliothek, and the Library of Congress. .env.example sets HARDCOVER_IMPORT_SEARCH_ENABLED and GOOGLE_BOOKS_IMPORT_SEARCH_ENABLED to false; set either to true once its credential is configured.
  • At least one book import source must be able to answer. Disabling every source, or enabling only Hardcover and Google Books without their credentials, stops the backend from starting.
